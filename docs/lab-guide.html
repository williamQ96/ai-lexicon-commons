Plale Lab terminology guide

A versioned internal proposal, open for discussion.

Plale Lab · Proposed / not ratified

Version 1.1 / Updated 2026-10-10

No consensus decision recorded.

Workflow and Harness

Initial proposal: Workflow is a general arrangement of work; deterministic Python code as well as LLM-based work can participate in a workflow.

Initial proposal: a harness is a workflow designed for an LLM or agent. Editorial revision for discussion: distinguish the execution layer from the process it supports. This edition uses supports/orchestrates rather than declaring a Harness is-a Workflow relationship.

Model and LLM

Initial proposal: any input-to-output mapping may be called a model. This remains an intentionally broad, unratified interpretation, not a universal external definition.

Working revision: specify whether model means a representation, an executable representation, or a learned inference component. An LLM is a learned language model; its training, scale and scope should be described rather than reduced to an arbitrary parameter threshold.

Agent

Initial proposal: an agent builds on an LLM and external tools, with its distinguishing attributes still to be decided.

Working revision: reserve the general term for systems with bounded autonomy, goal-directed behavior, environmental feedback and an ability to act. Describe an LLM-based agent as one particular implementation using an LLM. Planning, persistent memory and self-learning are optional capabilities, not automatic universal requirements.

Editorial and adoption policy

Check external evidence in the fixed order: applicable institutional definitions, peer-reviewed papers, industry standards or first-party documents or preprints or academic materials, then internal proposals. Preserve uncertainty and differing scopes.

Use cited statements, typed relations and a quiet reading layout. Strict nesting is reserved for supported is-a relations. All proposals in this guide are unratified; only a documented consensus decision may authorize green adoption tags.

Schema: an unratified editorial extension

Proposed extension: use schema for an explicit, versioned description of data structure, field meanings and stated constraints. Keep the data instance, the description and the validator separate; the same document can occupy different roles under a meta-schema.

Schema extraction is a process that recovers declarations or infers a description from evidence. Record the input population, source-to-field evidence, dialect/version, observed versus declared or inferred constraints, and unresolved coverage. A sample is not proof of every permitted record or intended semantic rule.
